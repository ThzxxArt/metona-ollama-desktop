> 版本：0.18.0-plan-v4

> 主题：**连接方式重构 + 交互减法 + 工程基座升级 + 文档与品牌重写**

## 一、背景与目标

### 1.1 为什么做 0.18.0

当前版本已经具备完整的 Agent Loop、33 个内置工具、MCP、记忆、上下文压缩、Plan Mode 和多平台安装包，但存在五个结构性问题：

1. **Ollama 连接层是“本地客户端”假设**：只有 `serverUrl`，没有 API Key，没有本地/远程模式区分，渲染进程直接 `fetch`，主进程只靠 CORS 白名单放行。
2. **设置项与模型调用存在历史包袱**：Temperature 硬编码在 5 处；上下文长度是固定 8 档下拉框；用户无法自由输入。
3. **工程基座偏重**：`ipc.ts` 734 行、`agent-engine.ts` 2,471 行、`tool-registry.ts` 1,672 行、`context-manager.ts` 1,622 行；SQLite 采用 `sql.js` 全库快照；没有 CSP，`sandbox: false`。
4. **工具数量与模式复杂度偏高**：33 个工具对模型选择造成噪声，Plan Mode 又是一层额外分支；0.18 将工具精简到 18 个，并移除 Plan Mode。
5. **文档与品牌落后**：README 还是中英混排；API 文档是 0.12.6 时代快照；DEVELOPMENT.md 仍写 Gitee/Windows-only；菜单里还有 Gitee 地址。

### 1.2 0.18.0 目标

- 让 Metona 同时支持**本地 Ollama**、**自建远程 Ollama**、**Ollama Cloud**。
- API Key 非必填；设置后所有 Ollama 接口必须携带 `Authorization: Bearer`。
- 远程自建服务支持**自动/手动卸载模型**，兼顾资源紧张场景。
- 删除 Temperature，把采样权交还模型默认配置。
- 上下文长度改为手动输入，按模型上限钳制。
- 完成 Electron / Vite / Vitest / TypeScript / electron-builder 等核心依赖升级。
- 完成 IPC、Agent、Tool、Context、DB 的模块化拆分。
- 完成 README 中文重写、README.en.md、SVG 横幅、截图、徽章和 API 文档更新。
- **工具从 33 个精简到 18 个**，合并重复能力，减少模型选择噪声与 schema token。
- **彻底移除 Plan Mode**，删除 `plan_track`、计划追踪器、Plan 确认弹窗和所有相关分支。
- 原计划中“可以在 0.18.0 完成”的能力全部纳入 0.18.0，不拆版本、不向后延。
- 已确认采用 TypeScript 6.0.3、`node:sqlite`、自建远程默认自动卸载。
- **0.18.0 是破坏性变更**：不提供旧设置、旧工具名、旧备份、旧数据库、旧会话格式的兼容处理。
- **所有署名统一为 ThzxxArt**：LICENSE、package.json、README、菜单、文档、页脚、仓库说明全部一致。

### 1.3 兼容性政策（Breaking Change）

0.18.0 **不提供任何向下兼容**，不做迁移、别名、回退开关、双读双写、旧格式导入。具体：

- 旧设置键（`serverUrl`、`temperature`、`numCtx` 等）**不读取、不迁移**；用户需在新设置面板重新配置。
- 旧工具名（`read_multiple_files`、`tree`、`copy_file`、`move_file`、`browser_*`、`session_list`、`session_read`、`calculator`、`plan_track`）**不再注册、不再接受**。
- 旧 `.metona` 备份（v1/v2）**不再支持导入**；0.18.0 只使用新的 v3 格式。
- 旧 v0.17.2 SQLite 数据库**不读取、不迁移**；0.18.0 首次启动创建全新数据库。升级前如需保留历史数据，请自行备份原始 `metona.db`，但新版本不负责解析旧库。
- `sql.js` 及 `METONA_DB_ENGINE=sqljs` 回退**直接删除**。
- IndexedDB fallback / IndexedDB→SQLite 迁移**直接删除**。
- Plan Mode 及 `plan_track` **直接删除**，不保留隐藏入口、不保留旧快捷键、不保留兼容分支。
- 旧备份中的压缩摘要 `system` 行归一化逻辑**删除**；新库只写入新格式。
- 文档中的 Gitee、旧版本号、Plan Mode、33 工具说明**直接删除或替换**。

> 破坏性影响必须在 Release Notes 和 README 升级说明中明确写出：**升级会丢失旧本地会话/设置，需自行备份原始数据库**。

### 3.4 对本项目的直接影响

1. **远程模式必须支持 `https://ollama.com` 和自建远程地址**；API Key 只放主进程。
2. **删除 Temperature**：Ollama 0.40 在未显式传 sampler 参数时保留模型默认采样；硬编码 `0.7` 会覆盖模型推荐值。

4. **远程卸载模型**：自建远程需要及时释放资源；云服务不执行卸载。
5. **新字段利用**：`done_reason`、`prompt_eval_cached_count`、云模型字段、`think` 档位。

### 5.2 连接数据模型

```ts
type OllamaMode = 'local' | 'remote';
type RemoteKind = 'cloud' | 'self-hosted';

interface OllamaConnectionSettings {
  mode: OllamaMode;
  localUrl: string;
  remoteUrl: string;
  remoteKind: RemoteKind;
  contextLength: number;
  remoteAutoUnload: boolean;
  requestTimeoutMs: number;
}

interface OllamaConnectionView extends OllamaConnectionSettings {
  hasApiKey: boolean;
}
```

API Key 不进入上述结构，单独由主进程 SecretStore 管理。

### 5.3 API Key 规则

```ts
const headers: Record<string, string> = {
  'Content-Type': 'application/json',
  ...(apiKey ? { Authorization: `Bearer ${apiKey}` } : {}),
};
```

### 5.5 远程模型卸载

这是 0.18.0 的明确能力，不再是“远程一律不卸载”。

#### 策略

```ts
interface RemoteUnloadPolicy {
  autoUnload: boolean;      // 自建远程默认 true
  unloadOnNewSession: boolean; // 与 autoUnload 共用
  unloadOnExit: boolean;    // 与 autoUnload 共用
}
```

- **本地**：保持现有行为，新建会话/退出释放显存。
- **远程自建**：默认 `autoUnload = true`，新建会话和退出都尝试卸载；用户可关闭。
- **远程 Ollama Cloud**：`autoUnload = false` 且不可开启；云端模型由服务端管理。
- **手动释放显存**：
  - 本地：直接执行。
  - 远程自建：允许；如果检测到多个模型，二次确认“可能影响其他用户”。
  - 远程云：禁用并提示。

#### 执行流程

```ts
async function unloadRemoteModels(client: OllamaClient): Promise<void> {
  if (client.remoteKind === 'cloud') return;
  if (!settings.remoteAutoUnload) return;

  const ps = await client.ps();
  const models = ps.models ?? [];
  await Promise.allSettled(
    models.map(m => client.generate({ model: m.name, keep_alive: 0 }))
  );
}
```

- 卸载请求必须携带 API Key。
- 退出时 `Promise.race` 超时（默认 5s），不阻塞退出。
- 失败只写日志，不阻塞。
- 新建会话时如果当前没有运行模型，跳过请求。
- 远程服务器资源紧张时，用户可开启“新建会话立即卸载”，避免旧模型占显存。

- TS 7.0 是 Go 原生编译器，7.0 没有稳定 programmatic compiler API，7.1 才计划提供。
- `typescript-eslint` 8.72 依赖旧 API；直接上 TS7 会破坏 lint。
- 当前 `tsconfig.main.json` 使用 `moduleResolution: "node"`，在 TS7 是硬错误，需要改 `node16/nodenext`。
- 0.18.0 先用 6.0.3 清理弃用项；0.19 再评估 7.1 + Oxlint/新 ESLint。
